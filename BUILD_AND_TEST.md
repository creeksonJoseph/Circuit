# CIRCUIT — Build and Test Guide

This document is the authoritative command reference for the repository. It is
written for both humans and future agents.

**Stage 1 status:** scaffold only. The program has a single `initialize`
instruction. Offer, escrow, settlement, and matching logic do not exist yet.

---

## 1. Non-negotiable stack decisions

1. The **SDK is Python** (`packages/sdk`), managed with **uv**. Do not create a
   TypeScript SDK and do not use `pip` or `python3 -m venv` directly.
2. The **frontend is React + JavaScript/JSX** (`app`). Do not convert it to
   TypeScript.
3. The **matcher** (`packages/matcher`) and **integration tests** (`tests`) are
   TypeScript. They consume the Anchor TypeScript client and
   `@solana/web3.js` 1.99.0.
4. Pin the versions in `PROPOSED_DEPENDENCIES.md`. Do not upgrade Anchor,
   Solana, web3.js, or TypeScript during a feature stage without review.
5. `anchor test` must use `--validator legacy`. Anchor 1.2.2 defaults to
   surfpool, which is not installed.

### 2.1 PATH

The toolchain is installed per-user. Add this to the shell profile if it is not
already present:

```bash
export PATH="$HOME/.cargo/bin:$HOME/.local/share/solana/install/active_release/bin:$HOME/.local/bin:$PATH"
```

### 2.2 Verify everything

```bash
bash scripts/check-toolchain.sh
```

```text

rustup active:        1.99.1-x86_64-unknown-linux-gnu (default)

```

### 2.3 Wallet

The test wallet must live **outside** the repository:

```bash
solana-keygen new --no-bip39-passphrase --outfile ~/.config/solana/id.json
solana config set --url localhost
solana config set --keypair ~/.config/solana/id.json
```

`Anchor.toml` already points at `~/.config/solana/id.json`.

The local program keypair is generated by `anchor build` under
`target/deploy/`. `target/` is gitignored. Never commit it.

## 4. Program: build and test

### 4.1 Build

```bash
anchor build --arch v3 --tools-version v1.57
```

This produces:

```text
target/deploy/circuit.so
target/idl/circuit.json
target/types/circuit.ts
```

It also copies:

- the IDL to `packages/sdk/src/circuit_sdk/idl/circuit.json`
- the TypeScript types to `packages/matcher/src/generated/circuit.ts`

### 4.2 Local integration test

```bash
NO_DNA=1 anchor test --validator legacy
```

What happens:

1. Anchor builds the program.
2. Anchor starts `solana-test-validator` on localnet.
3. Anchor deploys the program.
4. Anchor sets `ANCHOR_PROVIDER_URL` and `ANCHOR_WALLET`.
5. Anchor runs `[scripts] test`, which is
   `npm run test:integration -w @circuit/tests`.
6. Mocha runs `tests/tests/**/*.ts`.
7. Anchor shuts the validator down.

The Stage 1 suite verifies:

- the `ProtocolConfig` PDA is created with version `1`;
- a second initialization of the same PDA fails.

### 4.3 Manual validator workflow

Use this when debugging a single test:

```bash
# Terminal 1
solana-test-validator --reset

# Terminal 2
anchor build --arch v3 --tools-version v1.57
anchor deploy --provider.cluster localnet

# Terminal 3
ANCHOR_PROVIDER_URL=http://127.0.0.1:8899 \
ANCHOR_WALLET=$HOME/.config/solana/id.json \
npm run test:integration
```

### 4.4 Rust static checks

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
```

## 5. Python SDK

The SDK is managed with **uv**. `uv` creates `packages/sdk/.venv`, resolves
dependencies into the committed `uv.lock`, and builds the wheel. The virtualenv
and build outputs are gitignored.

### 5.1 Setup

Install uv once if it is missing:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
uv --version   # expected: uv 0.13.7
```

Then synchronise the environment exactly from the lockfile:

```bash
cd packages/sdk
uv sync --locked
```

`uv sync` creates `.venv/` and installs the package plus the `dev` dependency
group. Do not use `pip` or `python3 -m venv` for this project.

### 5.2 Test

```bash
uv run pytest
```

### 5.3 Build a wheel

```bash
uv build --wheel
ls -1 dist/
```

Expected:

```text
circuit_sdk-0.1.0-py3-none-any.whl
```

`uv build` uses an isolated build environment and the backend pinned in
`[build-system]` (`setuptools==78.1.1`, `wheel==0.48.0`). No global Python
packages are modified.

### 5.4 Root shortcuts

```bash
npm run test:sdk
npm run build:sdk
```

These run `scripts/test-sdk.sh` and `scripts/build-sdk.sh`, which run
`uv sync --locked` and then `uv run pytest` or `uv build --wheel`.

### 5.5 Lockfile

`packages/sdk/uv.lock` is committed. After changing `pyproject.toml`, refresh
it deliberately:

```bash
cd packages/sdk
uv lock
```

Then re-run the tests and the build. Do not run `uv sync` without `--locked` in
CI or in the helper scripts.

### 5.6 Rules for future agents

- Keep the SDK in Python and manage it with **uv**.
- Do not add a TypeScript SDK package.
- Do not add runtime dependencies until the SDK implementation stage, and pin
  them exactly when added.
- Keep amounts as integer base units.
- The SDK must not hold private keys.

```bash

```

Output: `packages/matcher/dist/`.

### 6.2 Test

```bash

```

Stage 1 tests verify the package version and that `findCycles` fails loudly
instead of returning a misleading empty result.

### 6.3 Type check

```bash

```

### 6.4 Rules for future agents

- The matcher stays TypeScript.
- It is untrusted; it never signs or gains privileges.
- It must not depend on the Python SDK at runtime.
- Amounts are `bigint`, never JavaScript `number`.

## 7. React frontend

The frontend is **JavaScript and JSX only**. Do not add `.ts` or `.tsx` files
under `app/`.

### 7.1 Development server

```bash
npm run dev -w @circuit/app
```

Open `http://127.0.0.1:5173`.

### 7.2 Production build

```bash
npm run build -w @circuit/app
```

Output: `app/dist/`.

### 7.3 Preview the production build

```bash
npm run preview -w @circuit/app
```

Open `http://127.0.0.1:4173`.

### 7.4 Environment

```bash
cp .env.example .env
```

Only `VITE_*` variables reach the browser. Never expose a private key or seed
phrase. The frontend signs through a wallet adapter in a later stage; it never
reads key material from the environment.

## 10. Full build order

Run stages in this order; later steps depend on generated artifacts:

```bash
# 1. Toolchain
bash scripts/check-toolchain.sh

# 2. JavaScript dependencies
npm install

# 3. Anchor program + IDL/types
anchor build --arch v3 --tools-version v1.57

# 4. Rust static checks
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings

# 5. TypeScript matcher
npm run build -w @circuit/matcher
npm run test -w @circuit/matcher

# 6. Python SDK
npm run test:sdk
npm run build:sdk

# 7. Frontend
npm run build -w @circuit/app

# 8. Integration tests (starts and stops the validator)
NO_DNA=1 anchor test --validator legacy

# 9. Repository-wide checks
npm run typecheck
npm run lint
npm run format:check
```

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `anchor test` looks for `surfpool` | Anchor 1.2.2 default validator | Add `--validator legacy` |
| `anchor: command not found` | PATH missing | Export `~/.cargo/bin` and the Solana bin directory |
| `cargo-build-sbf: command not found` | Solana CLI not on PATH | Export `~/.local/share/solana/install/active_release/bin` |
| Platform tools download stalls | Large first-time download | Retry on a stable connection; it is cached afterwards |
| Rust build killed | Low available RAM | Close memory-heavy apps; use the existing swap |
| `target/types/circuit.ts` missing | Program not built | Run `anchor build` first |
| `Initialize` fails with "account already in use" | Config PDA already initialized | Expected on a reused ledger; run `solana-test-validator --reset` |
| npm peer warnings about web3.js | Multiple major lines | The root `overrides` pin forces 1.99.0; do not remove it |
| Frontend build fails on `Buffer`/`process` | web3.js browser globals | Keep `vite-plugin-node-polyfills` configured |
| `uv: command not found` | uv not installed or not on PATH | `curl -LsSf https://astral.sh/uv/install.sh \| sh`, then export `~/.local/bin` |
| `uv sync --locked` reports a stale lockfile | `pyproject.toml` changed | Run `uv lock`, review the diff, re-run tests |

## 13. Security notes for build commands

- `target/deploy/*-keypair.json` is a real keypair. `target/` is gitignored.
- `~/.config/solana/id.json` is outside the repository and must stay there.
- `.env` is gitignored; `.env.example` contains public values only.
- Do not add `--verifiable` or Docker bootstrap flags until the dependency
  baseline is reviewed.
- Do not deploy to mainnet.
